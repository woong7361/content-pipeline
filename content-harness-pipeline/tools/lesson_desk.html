차시 작업대

화면에서 본 것을 차시마다 종류와 함께 적으면 바로 AI 가 처리합니다. 대기열 위에서부터 차례로 하고, 순서는 바꿀 수 있습니다. 빌드는 빌드·화면 결함 검사·기능 테스트만 합니다(AI 없음). KB 서버 전송은 하지 않습니다.

코드 메모 → 클로드가 차시 폴더 안의 일을 무엇이든(파일 고치기 · 이름 바꾸기 · 데드코드 정리 · md 대로 하기) · 그림 메모 → 코덱스가 그림을 다시 구움 · 검증 메모 → 빌드 후 코덱스가 화면을 열어 확인만 함

사용법눌러서 펼치기 · 접기

한눈에

  1. 왼쪽 사이드바의 학년 · 학기 · 차시 버튼으로 볼 차시를 고릅니다(스크롤해도 따라옵니다). 보이는 카드만 바뀌고, 다른 차시에서 돌던 작업은 계속됩니다. 처리 중인 차시에는 ● 가 붙습니다.
  2. 차시 카드에서 [화면 보기]로 빌드된 화면을 봅니다.
  3. 고칠 것이 보이면 종류(코드 · 그림 · 검증)를 고르고 메모 칸에 적은 뒤 [적기](또는 Enter — 줄을 바꾸려면 Shift+Enter). 누르면 바로 처리가 시작됩니다.
  4. 여러 개를 연달아 적으면 대기열에 쌓이고 위에서부터 처리됩니다(코드와 그림은 함께 돕니다 — 아래 '대기열과 순서').
  5. 끝난 메모는 처리된 메모로 내려갑니다. 대기열이 다 비면 자동으로 빌드됩니다. 메모에 "아직 화면 반영 전"이 붙어 있으면 빌드가 끝나지 않은 것이니 기다리세요. "화면 반영됨"으로 바뀌면 [화면 보기](열어 둔 화면은 새로고침)로 확인하고 [완료]로 닫습니다.

  • 한 메모에 한 가지만 적으면 결과를 보기 쉽습니다.

대기열과 순서

  • 화면 캡처는 메모 칸에 Ctrl+V 로 붙여 넣거나 끌어다 놓으면 칸 아래에 작은 그림으로 쌓입니다(✕ 로 빼기, 한 메모에 10장까지). [적기] 때 같이 올라가고, 처리하는 AI 가 그 그림을 열어 봅니다. 그림만으로는 못 적고 무엇을 고칠지 글이 있어야 합니다.
  • 새 메모는 기본으로 대기열 맨 뒤에 들어갑니다. [적기] 위의 칸에서 "U05 앞에"처럼 고르면 그 메모 앞에 끼워 넣습니다.
  • 처리 전(대기) 메모는 [고치기]로 글을 고칩니다. Enter 저장 · Shift+Enter 줄바꿈 · Esc 취소. 고치는 사이 AI 가 그 메모를 집어 가면 칸이 닫히고 고친 글은 저장되지 않습니다 — 확실히 고치려면 먼저 [멈춤].
  • 종류를 잘못 골랐으면 메모 오른쪽의 종류 칸에서 바꿉니다. 대기 중이면 종류만 바뀌고, 이미 처리된 메모는 바꾼 종류의 AI 에게 다시 맡깁니다(앞서 다른 AI 가 바꾼 것은 그대로 남습니다). 처리 중인 메모는 바꿀 수 없습니다.
  • 대기 중인 메모는 ↑ ↓ 로, 또는 ⠿ 를 잡고 끌어서 다른 대기 메모 사이에 놓아 순서를 바꿉니다(놓을 자리에 파란 줄이 보입니다). 처리 중인 메모는 옮기거나 지울 수 없고, 그 위로 끌어 놓을 수도 없습니다.
  • 한 번에 대기열 맨 앞의 같은 종류가 연달아 있는 묶음을 AI 한 번에 맡깁니다(AI 를 부를 때마다 고정비가 들어서). 예: 코드·코드·그림·코드 → [코드 2개] → [그림] → [코드].
  • 코드(클로드)와 그림(코덱스)은 서로 기다리지 않고 함께 돕니다. 코드끼리, 그림끼리는 한 번에 하나씩입니다. 검증만 칸막이라 위의 것이 다 끝나야 돌고, 아래 것은 검증이 끝날 때까지 기다립니다(검증은 빌드된 화면을 보므로 그사이 코드가 바뀌면 안 돼서). 예: 코드 A · 그림 B · 코드 C · 검증 D → A 와 B 가 함께 → A 가 끝나면 C → 다 끝나면 D.
  • 작업 하나가 끝날 때마다 대기열을 다시 읽으므로, 도는 중에 끼워 넣거나 순서를 바꿔도 바로 반영됩니다.
  • 여러 개를 순서까지 정해 놓고 돌리고 싶으면 먼저 [멈춤]을 누르고 적은 뒤 [다시 시작]을 누릅니다.

처리가 끝나면

  • 결과가 조금 아쉬우면 [보완해서 다시 맡기기] — 칸에 고칠 점만 적으면, 원래 메모와 지난 결과를 함께 AI 에게 넘겨 같은 메모를 다시 처리합니다. 보완한 내용은 메모 아래에 "보완 1, 2…"로 남습니다. 같은 내용 그대로 다시 하려면 [다시 맡기기].
  • 그림 메모가 바꾼 그림의 경로(작업 경로 기준, 예: assets/ui/btn.png)와 고침·새로 만듦이 결과 아래에 늘 보입니다.
  • 그림 메모가 그림을 고치거나 새로 만들었으면 [그림 보기] 버튼이 생깁니다. 누르면 작업 전 · 후를 나란히 보여 줍니다(새 그림은 후만). ← → 로 넘기고 Esc 로 닫고, [원본 새 탭 ↗]으로 원본을 엽니다. 노란 선이 그림 크기(캔버스), 빨간 점선이 투명하지 않은 내용이 있는 곳 — 그 사이가 투명 여백이고, 아래에 픽셀 크기 · 줄인 비율 · 여백(px · %)이 적힙니다. 기본은 화면에 맞춰 줄이기만 하고(키우지 않음, 전 · 후 같은 비율), [실제 크기 (100%)]로 원래 크기를 봅니다.
  • 메모 아래에 결과 배지와 한 줄 요약만 보입니다. 무엇을 어떻게 바꿨는지와 작업 기록은 ▸ 를 눌러 펼쳐 봅니다(기본은 접힘).
  • 처리된 메모는 최근에 적은 것이 맨 위입니다. 대기열은 처리 순서 그대로입니다.
  • 된 것(고침 · 그림 새로 구움 · 검증 통과) → 확인 대기. 화면을 보고 [완료]를 누릅니다.
  • 안 된 것(그림 필요 · 확인 필요 · 못 고침 · 검증 실패) → 열림. 이유가 메모 아래에 적힙니다. 저절로 다시 돌지 않습니다 — 같은 이유로 또 실패하며 비용만 들어서요. 새로 적거나 [다시 맡기기]를 누릅니다.
  • AI 작업 전 파일은 따로 복사해 둡니다. 실패하면 그 작업이 바꾼 것을 되돌립니다.
  • 자동 빌드 — 대기열이 다 비고 도는 작업(클로드 · 코덱스 둘 다)이 끝나면 한 번 빌드합니다(빌드 → 화면 결함 검사 → 기능 테스트). 이번에 코드·그림이 실제로 바뀌었을 때만 하고, [멈춤]으로 세웠을 때는 하지 않습니다. 작업마다 빌드하지 않는 것은 한 번에 4분쯤 걸려 대기열이 밀리기 때문입니다.

AI 모델

  • 사이드바 맨 아래 ▸ AI 모델을 눌러 펼친 뒤 클로드와 코덱스 모델을 고릅니다(접혀 있어도 지금 고른 것이 한 줄로 보이고, 펼친 상태는 기억합니다). 차시 작업대와 초안 파이프라인이 같은 설정을 씁니다.
  • 클로드 — 코드 메모, 초안의 기획~개발 단계 · 코덱스 — 그림·검증 메모, 초안의 그림 굽기.
  • 고르면 바로 저장되고 다음 작업부터 적용됩니다. 도는 작업은 원래 모델로 끝까지 갑니다.
  • 모델 아래 추론 강도(Low · Medium · High · Extra high · Max, 코덱스는 Ultra 까지)도 고릅니다. 고른 모델이 지원하는 것만 보이고, "기본(추천: …)"은 그 모델의 추천값입니다. 강도가 높을수록 꼼꼼하지만 느리고 비용이 늘어납니다.
  • 클로드는 주 모델(Opus 5.5 · Fable 5.1 · Sonnet 5.5 · Haiku 4.5) 아래 "그 밖의 버전"(Opus 4.8 · 4.7 · 4.6 등)이 있습니다.
  • 목록에 없는 모델은 직접 입력…을 고르고 이름을 적은 뒤 Enter. "기본"은 각 CLI 에 설정된 모델입니다.
  • 어떤 모델로 돌았는지는 AI 사용량 표의 "종류 · AI" 칸 괄호에 나옵니다.

알림

  • 작업대가 켜져 있으면 브라우저를 닫아도 Windows 바탕화면 알림이 뜹니다.
  • 실패하면 바로 — 어느 차시의 무슨 작업이 왜 실패했는지(예: "코덱스 로그인이 끊겼습니다 — codex login 후 [다시 맡기기]").
  • 대기열이 다 끝나면 — 자동 빌드까지 끝난 뒤 한 번: 고침 · 못 한 것 · 실패 수와 "화면에 반영됨".

AI 사용량

  • 카드 아래 AI 사용량을 펼치면 AI 작업마다 입력·출력 토큰, 비용, 걸린 시간이 나옵니다.
  • 차시마다 최근 10개만 남기고 오래된 것은 지웁니다.
  • 비용은 클로드만 나옵니다. 코덱스는 토큰만 알려 줍니다. 입력 토큰의 괄호 안은 캐시에서 읽은 양입니다.
  • 토큰 단위: 1a = 1토큰, 1b = 1,000a, 1c = 1,000b(100만), 1d = 1,000c. 소수 첫째 자리까지 나옵니다.

알아 둘 것

  • AI 는 gyo6 차시 폴더를 직접 고칩니다. 고친 뒤 gyo6 에서 커밋해야 서버 배포(npm run deploy)가 됩니다.
  • 한 차시에서는 작업이 하나씩만 돕니다. 다른 차시는 동시에 돌아갑니다.
  • 작업 경로가 …/lessons/학기/차시 모양이 아니면(예: 파이프라인 run 폴더) 코드·그림만 되고 빌드·검증은 안 됩니다.
  • 작업대를 끄면(Ctrl+C) 돌던 작업은 끊깁니다. 다음에 켤 때 그 작업을 되돌리고 그 차시 대기열을 멈춤으로 둡니다. [다시 시작]을 누르세요.
  • 작업 로그는 카드 아래 로그 끝부분에서 보고, 전체는 desk/학기-차시/jobs/ 에 있습니다.
