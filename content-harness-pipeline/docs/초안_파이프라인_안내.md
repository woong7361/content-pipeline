# 초안 파이프라인 상세 안내

> 2026-10-01 기준. 코드: `produce_lesson.py`(초안) · `install_lesson.py`(배치) · `verify_lesson.py`(화면 검증).
> 화면: 바탕화면 「차시 작업대」 → 위쪽 **초안 파이프라인** 탭(http://127.0.0.1:8790/pipeline).
> 차시 작업대 쪽 설명은 [작업대_안내.md](작업대_안내.md).

---

## 1. 목적

**스토리보드 PDF 하나 → gyo6 가 바로 읽는 차시 번들**을 만든다.

```text
runs/{run}/lesson/
  lesson.json        장면 · 대사 · 문제 · 정답 · 연출 데이터 (gyo6 공통 런타임이 읽는다)
  player-ext.js      이 차시 전용 동작
  player-ext.css     이 차시 전용 스타일
  assets/            그림 (배경 · 인물 · UI)
  manifest.json      코드가 만든다 (AI 가 쓰지 않는다)
  page-map.md        스토리보드 쪽 ↔ 화면 대응표
```

사람 제작팀의 일하는 순서(기획 → 디자인 → 인터뷰 → 지침 → 비주얼 → 개발·그림)를 AI 단계로 나눴다.
한 번에 "차시 만들어 줘" 를 시키지 않는 이유 — 단계마다 산출물을 파일로 남겨 **사람이 중간에 보고 고칠 수 있고**,
어느 단계에서 무엇이 빠졌는지 **추적**할 수 있게 하려는 것이다.

## 2. 전체 흐름

```text
스토리보드 PDF
   │  ① 읽을 수 있나 검사 (한글이 추출되나 · 쪽 수)
   ▼
기획 senior_planner ─────────────▶ planning/content-plan.md
   ▼
디자인 senior_designer ──────────▶ design/wireframe.md · design/concept.md
   ▼
인터뷰 질문지 ───────────────────▶ interview/questions.md        ⏸ 멈춤 ① 사람이 답한다
   ▼
제작 지침 interview_brief ────────▶ planning/production-guide.md
   ▼
요구 명세 lesson_spec ────────────▶ spec/lesson-spec.json          (멈추지 않음 — 못 정한 것은 AI 가 정해 interview/assumed.md 에)
   ▼
비주얼 설계 visual_design ────────▶ design/visual-design.md · asset-plan.md · asset-plan.json
   │  ② 그림 계획 검사 (규격과 대조, 어긋나면 되먹여 다시)
   ▼
   ├──────────────────────────────┬──────────────────────────────┐
개발 senior_developer (클로드)        그림 굽기 asset_render (코덱스)      ← 동시에
 lesson.json · ext · page-map        lesson/assets/**
 ③ 게이트 되먹임 재시도 · 자가 검사     ④ 기준 그림 · 크로마 · 여백
   ├──────────────────────────────┴──────────────────────────────┘
   ▼
디자인 검토 기록 · 산출물 검사 · manifest 생성 ─▶ 끝 (데이터만 본다)
   ▼
(음성 대본 — 대시보드에서는 건너뜀)
   ▼
gyo6 에 넣기: 배치 install_lesson → 빌드 build:lesson → 화면 검증 verify_lesson
   ▼
차시 작업대에서 사람이 보고 다듬기
```

## 3. 단계별 상세

| # | 단계 | 누가 | 읽는 것 | 내는 것 | 하는 일 |
|---|---|---|---|---|---|
| 1 | **기획** `senior_planner` | 클로드 | 스토리보드 원본(쪽 그림 포함) | `planning/content-plan.md` | 장면 · 문항 · 보기 · 정답 · 대사 · 연출을 **요약 없이** 옮기고 쪽 출처를 단다 |
| 2 | **디자인** `senior_designer` | 클로드 | content-plan | `design/wireframe.md` · `concept.md` | 화면 구성 · 인물 배치 · 흐름 |
| — | **인터뷰 질문지** | 코드 | 앞 단계들이 낸 질문 | `interview/questions.md` | 원문이 비워 둔 것(정답 · 애매한 연출 등)을 질문으로 모은다 |
| 3 | **제작 지침** `interview_brief` | 클로드 | 계획 · 와이어 · 콘셉트 + **사람 답** | `planning/production-guide.md` | 답을 반영해 개발 지침으로 정리 |
| 4 | **요구 명세** `lesson_spec` | 클로드 | 계획 · 지침 · 와이어 · 콘셉트 | `spec/lesson-spec.json` | 기계가 검사할 수 있는 명세(문항 · 정답 · 판정 규칙). **정할 것(DEC-…)**은 다시 묻지 않고 근거 있는 값으로 정해 `interview/assumed.md` 에 모은다(2026-10-02 — 인터뷰는 한 번) |
| 5 | **비주얼 설계** `visual_design` | 클로드 | 명세 · 와이어 · 콘셉트 + 그림 규격 문서 | `visual-design.md` · `asset-plan.md` · **`asset-plan.json`** | 화풍 · 색 · 그림 목록과 그림마다 지시(mustInclude · 비울 자리 · 금지) |
| 6 | **개발** `senior_developer` | 클로드 | 계획(원본) · 지침 · 명세 · 비주얼 · 그림 계획 + lesson 계약서 | `lesson/lesson.json` · ext · `page-map.md` · `development-notes.md` | gyo6 런타임이 읽는 데이터로 옮긴다 |
| 7 | **그림 굽기** `asset_render` | **코덱스(고정)** | `asset-plan.json`(또는 lesson.json) | `lesson/assets/**` | 그림을 실제로 생성해 저장 |
| — | **검사** | 코드 | 산출물 전부 | `manifest.json` · 검사 결과 | 게이트 · 계약 위반 · 빠진 그림 · 알파 확인 |

### 왜 개발 단계가 "원본 계획"까지 읽나

중간 단계가 요약하면 하류는 **그 존재 자체를 모른다**. 실측(2026-09-11, 3-1/05) — 기획이 장면별 인물 위치를 정확히 적었는데,
제작 지침이 요약하며 떨어뜨렸고 개발 단계는 원본 계획을 볼 수 없어 인물이 전 장면 왼쪽에 고정됐다.
그래서 개발 단계의 입력에 `content-plan.md` 를 넣었다(프롬프트 문구보다 입력 연결이 먼저).

## 4. 멈춤점 — 사람이 하는 일

| 멈춤 | 언제 | 사람이 할 일 | 대시보드에서 |
|---|---|---|---|
| ⏸ ① **인터뷰** | 디자인 단계 직후(대시보드는 항상 여기서 멈춘다) | 질문마다 답 적기. 모르면 비워 둔다 — **비운 칸은 이후 단계가 지어내지 않는다** | 답 칸에 적고 [답 저장하고 이어서 만들기] |
| ~~⏸ ② 정할 것~~ | 2026-10-02 부터 멈추지 않는다 — AI 가 정한 것은 `interview/assumed.md` | 끝난 뒤 훑어보고, 틀린 것만 질문지에 답 적고 다시 돌리기 | 산출물 카드 인터뷰 칸 |
| (③ 음성) | 초안이 끝나고 인물 대표 그림이 있을 때 | Typecast 웹 편집기에서 대사마다 음성을 만들어 내려받기 | 초안 실행은 건너뛰고(`--no-voice`), 받은 파일은 **[음성 파일 넣기]** 로 넣는다(아래) |
| (④ 기준 그림) | 그림 화풍을 처음 정할 때 | 기준 그림 한 장을 승인 | 아직 코드에 없음 — 사람이 순서를 지킨다 |

- 답은 `interview/questions.md` 에 `### Q번호. 질문` + `답: 한 줄` 모양으로 저장된다. 여러 줄 답은 " / " 로 잇는다.
- 저장 전 파일은 `questions.bak-{시각}.md` 로 남는다.
- 적던 답은 브라우저에 임시 보관돼, 다른 탭에 갔다 와도 남는다.

## 5. 품질 장치 (각 번호는 흐름도의 ①~④)

### ① 스토리보드 읽기 검사
PDF 에서 한글이 추출되지 않으면(스캔본 등) 멈춘다. 쪽 수가 표지의 History 표와 다르면 알린다(실측 4종 중 3종이 적게 적혀 있었다).

### ② 그림 계획 검사 (`asset_plan_check`)
비주얼 설계가 낸 `asset-plan.json` 을 그림 규격(`prompts/asset_spec_contract.md`)과 대조한다. 어긋나면 위반 목록을 그대로 되먹여 다시 부른다.
- 예: 인물은 **전신**(`"framing": "full-body"`, 머리 비율 약 0.238) — 실측(2026-09-23) "허리 위까지만" 으로 계획해 화면에서 인물이 작아졌다.
- 산문 판정은 거짓 양성이 나서 접었고, **값(필드)**만 본다.

### ③ 개발 단계 — 게이트 되먹임 + 자가 검사
- 촘촘한 게이트(`check_lesson_standalone`)에 걸리면 **걸린 목록을 그대로** 프롬프트에 넣어 다시 부른다(`--max-retries`, 기본 2).
  요약해서 주면 모델이 다른 곳을 고친다.
- 실패한 `lesson.json` 은 `.rejected` 로 치운다 — 남겨 두면 다음 실행이 "이미 있음" 으로 건너뛰어 깨진 것이 최종본이 된다.
- 끝내기 전에 자가 검사(`stages.scripts.self_check`)를 스스로 돌린다. 이 명령 하나만 허용된다.
- lesson 계약서(`prompts/lesson_contract.md`)를 함께 싣는다 — 게이트가 요구하는 규칙을 모델이 볼 수 있게.

### ④ 그림 굽기
- **기준 그림(스타일 앵커)**: 역할(배경 · 인물 · UI)마다 사람이 승인한 그림 한 장을 `--style-anchor` 로 고정하고, 나머지는 그 그림을 열어 외곽선 · 채색까지 맞춘다. 화풍의 정도는 말이 아니라 그림으로 준다.
- **투명 그림은 크로마**: 코덱스가 배경을 평평한 한 색(기본 마젠타)으로 칠해 저장하고, **지우는 것은 코드**다. 스스로 투명하게 만들면 작품을 파먹었다(실측).
- **여백 거의 없게**(2026-10-01): 투명 그림은 대상이 캔버스를 거의 채운다. 인물은 규격(발끝 · 머리 비율 · 감정 그림끼리 같은 위치)이 먼저.
- 투명이라고 적었으면 **알파를 실제로 잰다**. 같은 인물은 감정 그림을 연달아 그리며 앞 그림을 열어 대조한다.
- 한 호출에 6장까지(`--asset-batch-size`). 한 인물의 감정 묶음은 쪼개지 않는다.

### 개발 ∥ 그림 — 동시 실행
둘 다 `visual_design` 만 있으면 된다(그림은 `asset-plan.json` 을 본다). 실측으로 개발 18~36분, 그림 4~37분이라 겹치면 그만큼 빨라진다.
- 한쪽이 죽어도 다른 쪽은 끝까지 기다린다(반쯤 구운 그림을 남기지 않게).
- 끝나면 계획과 `lesson.json` 의 그림 목록을 대조한다 — 개발자가 경로를 바꿔 적으면 구운 그림이 고아가 되기 때문.

## 6. 다시 돌리기 · 캐시

- **입력 해시 캐시**: 단계마다 입력(상위 산출물 · 프롬프트 · 옵션)의 해시를 기억한다. 바뀐 게 없으면 "캐시 적중" 으로 건너뛴다.
  - `--no-cache`: 캐시를 안 쓰고 다시. `--invalidate <단계>`: 그 단계와 하위 단계만 무효화.
- **범위 지정**: `--start-at <단계>` 부터 `--through <범위>` 까지.

  | `--through` | 어디까지 |
  |---|---|
  | `planning` | 기획 |
  | `interview` | 디자인 + 질문지 (대시보드 [초안 만들기]의 기본) |
  | `design` | 비주얼 설계 |
  | `develop` | 개발 |
  | `render` | 그림 굽기 |
  | `all` | 끝까지 (기본) |

- 대시보드의 [이어서 만들기]는 끝난 단계를 캐시로 건너뛰고 나머지를 돈다. 인터뷰 전에 멈췄으면 올린 PDF 로 처음부터 다시 간다(끝난 단계는 캐시).

## 8. 초안 뒤 — gyo6 에 넣기와 화면 검증

`produce_lesson.py` 의 마지막 검사는 **데이터만** 보고 화면을 한 번도 열지 않는다. 그래서 끝나면 반드시
**배치 → 빌드 → 화면 검증**까지 돈다(대시보드의 [gyo6에 넣기]가 이것을 한 번에 한다).

### 넣을 곳 — 최종 산출 경로

[gyo6에 넣기] 위의 **최종 산출 경로** 칸에서 정한다(새 초안 때 적었으면 그 값이 들어 있다). 바꿔 적고 누르면 그곳에 넣고, run 마다 기억한다.
`<gyo6 체크아웃>\lessons\<학기>\<차시>` 모양이 아니거나 체크아웃(package.json)이 아니면 이유를 보여 주고 넣지 않는다.

### 배치 `install_lesson.py`
- run 의 `lesson/` 을 gyo6 `lessons/{학기}/{차시}/` 로 옮기고, 놓은 파일의 해시를 `install-record.json` 에 남긴다.
- **덮어쓰기여도** 지난 배치 뒤 gyo6 쪽에서 바뀐 파일이 있으면 멈추고 목록을 보여 준다(사람이 gyo6 에서 고친 것을 조용히 덮지 않게).
- 대시보드는 같은 차시가 있으면 막고 [덮어쓰기로 넣기]를 보인다.

### 화면 검증 `verify_lesson.py` — 싼 것부터 네 층

| 층 | 무엇 | AI |
|---|---|---|
| ① `check_rendered` | 깨진 그림 · 겹침 · 넘침 · 진행 막힘 | 없음 |
| ② `run_functional_tests` | 문항마다 오답 → 재시도 · 힌트 · 정답을 **실제로 풀어** 본다 | 없음 |
| ③ 캡처 | 전 화면(문제 상태 · 인증서 포함). 못 간 곳은 장면 이동으로 채운다 | 없음 |
| ④ `lesson_review` · `screen_diff` | 캡처를 보고 판정 / 스토리보드 예시화면과 대조 | 코덱스 2회 |

①② 가 막으면 ④ 는 건너뛴다(대시보드는 `--skip-llm` 으로 ①~③ 만).

### 걸린 것은 "고칠 수 있는 담당" 으로 나눈다 → `verify/to-{담당}.md`

| 담당 | 무엇이 오나 | 어떻게 보내나 |
|---|---|---|
| developer | 배치 · 겹침 · 기능 실패 · 원문과 다른 문구 · 그림↔좌표 불일치 | `--start-at senior_developer --through develop --screen-report verify/to-developer.md` |
| asset | 그림 자체가 잘못 그려진 것 · 못 구운 그림 | `--start-at asset_render --through render --rerender-from verify/to-asset.json` |
| storyboard | 화면 문구가 원문 그대로인데 틀렸다는 지적 | 원고 담당 확인 → 인터뷰 답으로 |
| runtime | 공통 런타임(player.js)에서 난 오류 | gyo6 쪽에 알림 |
| human | 판단 못 한 것 | 사람이 담당을 정함 |

고친 뒤에는 배치 → 빌드 → 검증을 다시 돈다. 그 뒤 사람 눈에 걸리는 것은 **차시 작업대**에서 메모로 다듬는다.

## 9. 대시보드에서 쓰는 법 (`/pipeline` 탭)

1. 왼쪽 **[+ 새 초안 만들기]** → run 이름(예: `g4l05`) · **최종 산출 경로**(선택) · PDF 를 고르고 [초안 만들기].
   - 최종 산출 경로 = 차시가 최종으로 놓일 폴더. `C:\…\gyo6_content\lessons\4-1\05` 처럼 **gyo6 체크아웃의 lessons\학기\차시**.
   - 차시만 적으면(`4-1/05`) 작업대가 보는 gyo6(`kb_contents_02\gyo6_content`)로 넣는다. 비워 두면 넣을 때 정한다.
   - 다른 체크아웃(예: `kb_contents\gyo6_content`)도 된다 — 배치 · 빌드 · 화면 검증을 그 체크아웃에서 한다.
     다만 차시 작업대는 설정한 gyo6 하나만 보므로 그 차시는 작업대에 안 나타난다.
2. 바탕화면 알림이 오면(또는 상태가 "답 대기") → 답 칸에 적고 **[답 저장하고 이어서 만들기]**.
3. 인터뷰 뒤에는 멈추지 않는다. AI 가 정한 것은 `interview/assumed.md` 에서 훑어본다.
4. "초안 끝" → 넣을 차시를 확인하고 **[gyo6에 넣기]**(배치 → 빌드 → 화면 검증).
5. 차시 작업대에 그 차시가 나타난다 → 화면을 보며 메모로 다듬는다.

**음성 넣기** — 개발 단계가 끝나 lesson.json 이 생긴 run 에는 **[음성 파일 넣기]** 상자가 나온다.
대사 한 줄마다 따로 받은 파일을 한꺼번에 올리면 자동으로 짝짓고(이름 속 대사 글자 → 번호 · 순서), 확인표에서 들어 보고 고친 뒤 [넣기].
run 의 `lesson/` 에 들어가므로 gyo6 에는 [gyo6에 넣기](같은 차시가 있으면 [덮어쓰기로 넣기])로 반영한다.
자세한 쓰는 법은 [작업대_안내.md](작업대_안내.md) 의 "음성 파일 넣기"(같은 부품이다).

화면에서 늘 보이는 것:
- **지금 단계**와 단계별 상태(끝남 · 캐시 · 도는 중 · 실패 · 대기).
- 실행마다 · 단계마다 **토큰 · 비용 · 시간**(1a = 1토큰, 1b = 1,000a, 1c = 1,000b).
- **산출물**: 단계 순서대로 파일 버튼(md · json → VS Code, [보기] → 화면 안), 그림 썸네일.

## 10. 비용 · 시간 감 (실측)

- 클로드는 "ok 만 답하라" 는 호출에도 입력 약 5만 토큰(약 $0.40)이 든다 — CLI 가 저장소 맥락을 매번 읽는 **고정비**.
- 개발 단계 18~36분, 그림 굽기 4~37분(동시에 돈다).
- 예: `g4l04`(4-1/04) 전체 기록 — LLM 호출 55회(실패 11회 · 재실행 포함), 클로드 비용 약 $33, LLM 시간 합 약 4시간 25분.
  다시 돌린 실행이 많이 섞인 값이라 한 번에 끝나는 초안은 이보다 적다.
- 기록은 `runs/{run}/usage-log.jsonl`(호출마다) · `usage-report.md`(표). 2026-09-29 이전 run 은 기록이 없다.

## 11. 실패에서 배운 규칙 (요약)

| 규칙 | 계기 |
|---|---|
| 스토리보드 세부는 **어느 단계에서도 요약하지 않는다**. 옮긴 항목에 쪽 출처를 단다. 못 옮긴 것은 `unmapped` 로 | 회차마다 손실 지점이 달랐다(planner 압축 → 지침 요약 → 예시화면 말풍선 누락) |
| 화풍은 **사람이 고른 기준 그림**으로 묶는다. 말로 정도를 주지 않는다 | 그림 전면 재생성이 5번 반복 |
| 옵트인 선언(`speechText` · `castOnStage: keep`)은 그 선언이 요구하는 나머지와 한 묶음 | 게이트 · 빌드 다 통과했는데 화면이 비어 있었다 |
| 연출 · 배치 지시는 산문이 아니라 **필드로만** 화면에 닿는다 | `action` 산문만 적어 아무 일도 안 일어났다 |
| 게이트는 배포 차시에서 **거짓 양성 0건**일 때만 넣는다 | 산문 키워드 게이트가 배포 차시에서 거짓 양성 3건 |
| 학습자 경로만 밟으면 문제 화면이 안 찍힌다 → 장면 이동으로도 찍는다 | 캡처 15장이 전부 컷씬 |
| base 가 `var(--…)` 통로를 냈으면 **변수만** 바꾼다 | 규칙으로 이기려다 화면을 두 번 깼다 |

전문은 `content-harness-pipeline/CLAUDE.md` 의 "실패에서 배운 것".

## 13. 명령 모음 (터미널에서 직접 돌릴 때)

```bash
cd content-harness-pipeline

# 인터뷰 직전까지
python -B ./produce_lesson.py "../스토리보드.pdf" --run-id g4l05 --gyo6-root {GYO6} --through interview --no-voice

# 답 적은 뒤 이어서 끝까지
python -B ./produce_lesson.py runs/g4l05 --gyo6-root {GYO6} --start-at interview_brief \
  --interview-notes runs/g4l05/interview/questions.md --no-voice

# 모델 · 추론 강도 지정
python -B ./produce_lesson.py runs/g4l05 ... --claude-model claude-opus-5-5 --codex-model gpt-5.5 --claude-effort high

# LLM 없이 다시 검사만
python -B ./build_lesson.py runs/g4l05 --gyo6-root {GYO6} --check-only

# 배치 → 빌드 → 화면 검증
python -B ./install_lesson.py runs/g4l05 --target {GYO6} --lesson 4-1/05
cd {GYO6} && npm run build:lesson -- 4-1/05
python -B ./verify_lesson.py runs/g4l05 --target {GYO6} --lesson 4-1/05 --skip-llm
```
