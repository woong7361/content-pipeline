## 한눈에 보기

두 도구는 하나의 흐름에서 앞뒤를 맡습니다.

```text
스토리보드 PDF ─▶ [초안 파이프라인] ─▶ gyo6 차시 폴더 ─▶ [차시 작업대] ─▶ 커밋 전 점검 ─▶ 커밋 · 배포(gyo6)
                   AI 전문가 단계                          사람 메모 → AI 수정
```

- **초안 파이프라인**: 스토리보드에서 차시 **초안**을 만든다.
- **차시 작업대**: 그 차시(또는 이미 있던 차시)를 사람 눈으로 보며 **다듬어** 커밋 직전까지 가져간다.

## 1. 초안 파이프라인 (`/pipeline` 탭)

### 목적

스토리보드 PDF 하나로 gyo6 가 바로 읽는 **차시 번들**을 만든다.

```text
lesson.json · player-ext.js · player-ext.css · assets/(그림) · manifest.json
```

실제 제작팀이 일하는 순서를 AI 단계로 나눴다(`produce_lesson.py`).

### 단계

| 단계 | 하는 일 | 누가 |
|---|---|---|
| 기획 | 스토리보드를 요약 없이 옮겨 콘텐츠 계획 작성 | 클로드 |
| 디자인 | 와이어프레임 · 콘셉트 | 클로드 |
| **인터뷰** | 원문이 비워 둔 것(정답 등)을 질문으로 뽑고 **사람이 답할 때까지 멈춤** | 사람 |
| 제작 지침 · 요구 명세 | 답을 반영해 정리. 정할 것이 남으면 다시 질문하고 멈춤 | 클로드 |
| 비주얼 설계 | 그림 목록 · 화풍 규격 | 클로드 |
| **개발 ∥ 그림 굽기** | lesson.json 작성과 그림 생성을 **동시에** | 클로드 ∥ 코덱스 |
| 검사 | 게이트 · manifest 생성 | 코드 |

### 화면에서 할 수 있는 것

- **[+ 새 초안 만들기]**: PDF 를 올리면 인터뷰 직전까지 자동으로 돈다.
- **인터뷰 답**: 질문마다 답 칸에 적고 [답 저장하고 이어서 만들기].
  - 적던 답은 다른 탭에 갔다 와도 남는다(이 브라우저에 임시 보관).
- **현황**: 지금 어느 단계인지, 단계마다 토큰 · 비용 · 시간.
- **산출물**: 단계별 파일 버튼.
  - md · json 은 누르면 VS Code 로 열린다. 옆 [보기]는 화면 안에서 본다.
  - 그림은 썸네일, 누르면 크게(← → 넘기기, Esc 닫기).
- **[gyo6에 넣기]**: 배치 → 빌드 → 화면 검증. 넣은 차시는 작업대에 바로 나타난다.
- **모델 선택**(사이드바 아래): 클로드 · 코덱스 모델과 추론 강도. 두 화면 공용.

### 지키는 원칙

- 스토리보드 세부(문항 · 보기 · 정답 · 대사)는 **어느 단계에서도 요약하지 않는다.**
- 화풍은 말이 아니라 **사람이 승인한 기준 그림**으로 묶는다.
- 그림을 구울 때 투명 그림은 **여백 거의 없이** 그린다(인물은 규격 우선).
- 산출물은 데이터 게이트와 **화면 검증**을 모두 통과해야 한다.

## 2. 차시 작업대 (`/` 탭)

### 목적

초안 파이프라인과 자동 검사가 못 잡고 **사람 눈에 걸리는 것**을 차시마다 적어 두면 AI 가 고치게 하는 곳.

- gyo6 차시 폴더(3-1 · 3-2 · 4-1 · 4-2)를 **직접** 고친다.
- run(초안)이 없는 기존 차시도 똑같이 다룬다.
- 왼쪽 사이드바에서 학년 · 학기 · 차시로 골라 본다(보이는 카드만 바뀌고, 작업은 서버에서 계속 돈다).

### 2-1. 메모와 대기열

차시 카드에 화면에서 본 것을 적고 종류를 고르면 **바로 처리**한다.

| 종류 | 맡는 AI | 하는 일 |
|---|---|---|
| **코드** | 클로드 | 차시 폴더 안의 무엇이든 — lesson.json · ext 고치기, 파일 이름 바꾸기(가리키는 곳까지), 데드코드 · 안 쓰는 파일 정리, 메모가 가리키는 md 대로 하기 |
| **그림** | 코덱스 | 그림 다시 그리기 · 새로 만들기(9-slice 포함). 투명은 크로마 색으로 칠하고 코드가 지운다 |
| **검증** | 코덱스 | 빌드된 화면을 열어 **확인만** 한다(파일을 안 바꾼다) |

- **그림 붙이기**: 메모 칸에 화면 캡처를 **Ctrl+V** 로 붙이거나 끌어다 놓는다(한 메모에 10장까지, 장당 15MB). [적기] 때 같이 올라가 `desk/{차시}/attachments/{메모 번호}/` 에 저장되고, 메모에 작은 그림으로 보인다(누르면 원본). 처리하는 AI 에게 그 그림 경로를 넘겨 **열어 보게** 한다. 글 없이 그림만은 못 적는다.
- **병렬**: 코드(클로드)와 그림(코덱스)은 동시에 돈다. 검증은 칸막이라 앞뒤를 기다린다.
- **순서 바꾸기**: 대기 중인 메모는 끌어 놓기 · ↑↓. 새 메모를 원하는 메모 **앞에** 끼워 넣을 수 있다.
- **글 고치기**: 대기 중인 메모의 [고치기]. Enter 저장 · Shift+Enter 줄바꿈 · Esc 취소. AI 가 이미 집어 간 메모는 못 고친다(고쳐도 반영이 안 되므로 서버가 거절한다).
- **종류 고치기**: 메모 오른쪽 종류 칸. 대기 중이면 종류만 바뀌고, 처리된 메모는 그 종류로 다시 맡긴다.
- 같은 종류가 연달아 있으면 한 번에 묶어 맡긴다(AI 호출 고정비를 아끼려고).

### 2-2. 결과 확인

- 메모마다 **결과 배지 + 한 줄 요약**. 자세한 설명과 작업 기록은 [자세히]로 펼친다(기본 접힘).
- 그림 메모는 **바꾼 그림 경로**가 늘 보이고, **[그림 보기]** 로 작업 전 · 후를 나란히 본다. 노란 선 = 그림 크기, 빨간 점선 = 내용이 있는 곳(그 사이가 투명 여백),
  아래에 픽셀 크기 · 줄인 비율 · 위아래좌우 여백(px · %). 화면에 맞춤은 줄이기만 하고 전 · 후 같은 비율, [실제 크기 (100%)] 로 원래 크기.
- 상태: 대기 → 처리 중 → **확인 대기**(된 것) / **열림**(못 한 것) → 완료.
  - AI 가 끝내도 **사람이 화면을 보고 [완료]** 를 누른다.
  - 열림은 저절로 다시 돌지 않는다(같은 이유로 또 실패하며 비용만 든다).
- 처리된 메모의 버튼:

  ```text
  [확인 대기] [화면 반영됨] [그림 보기]
  [다시 맡기기] [보완해서 다시 맡기기] [종류 ▾]
  [완료] [지우기]
  ```

  - **[다시 맡기기]**: 같은 내용으로 다시.
  - **[보완해서 다시 맡기기]**: 고칠 점만 적으면, 원래 메모 + 지난 결과 + 보완 메모를 함께 AI 에게 넘긴다. 보완 기록은 메모 아래에 "보완 1, 2…"로 쌓인다. 보완 칸에도 캡처를 Ctrl+V · 끌어 놓기로 붙인다(`attachments/{메모}/r{보완 번호}-img-N`, AI 가 그 보완과 함께 열어 본다).

### 2-3. 빌드와 안전장치

- **자동 빌드**: 대기열이 비고 실제로 파일이 바뀌었으면 빌드 → 화면 결함 검사 → 기능 테스트. 빌드에 들어간 메모가 표시된다.
- **빌드 지점 — [여기까지 빌드]**: 적기 칸 옆 버튼. 대기열 중간에 빌드를 끼워 넣는다.

  ```text
  대기열:  A(코드) · B(그림) · 🔨 여기까지 빌드 · C(코드)
  처리:    A ∥ B  →  빌드  →  C  →  (바뀐 게 있으면) 맨 끝 자동 빌드
  ```

  넣을 자리는 "대기열 맨 뒤에 / U05 앞에" 칸으로 고르고, 넣은 뒤에도 끌어서 옮길 수 있다.
- **버튼 위치**: [화면 보기] · [빌드] · [커밋 전 점검]은 화면 **오른쪽 사이드바**에 있다(왼쪽에서 고른 차시의 버튼, '전체 차시'면 보이는 차시마다). 화면이 좁으면 **왼쪽 사이드바 아래**로 옮겨진다. 사이드바 맨 아래 **AI 모델**은 눌러서 접고 편다.
- **[빌드]**: 사람이 직접 빌드(AI 없음). **KB 서버로 보내지 않는다** — 배포는 gyo6 에서 `npm run deploy`.
- **백업 · 되돌림**: 작업마다 작업 전 파일을 백업하고, 실패하거나 멈추면 **그 작업이 바꾼 것만** 되돌린다.
  - 코드는 차시 폴더 전체, 그림은 그림 파일만 백업한다. 동시에 돈 상대 작업의 결과는 건드리지 않는다.
  - AI 는 파일을 **지우지 못한다**(`rm` 차단). 지울 것은 `desk/{차시}/removed/` 로 옮긴다.
- **멈춤 두 가지**
  - **[이번 작업 끝나면 멈춤]**: 도는 작업은 끝까지 마치고 멈춘 뒤 빌드한다. 중간 결과를 볼 때.
  - **[지금 멈춤]**: 바로 끊고 그 작업을 되돌린다(그 작업의 AI 비용은 버려진다).
- **빌드 줄 세우기**: 같은 gyo6 에서 빌드는 한 번에 하나(서로의 임시 파일을 지우지 않게).
- **꺼졌다 켜지면**: 하던 작업을 되돌리고 그 차시를 **멈춤**으로 둔다(켜자마자 AI 비용이 나가지 않게).

### 2-4. 수정 요청서 (PDF)

외부에서 온 수정 요청 PDF 를 차시 카드에서 올린다(**차시 하나씩**).

1. 파일을 고르고 **[올려서 나누기]** — 클로드가 요청서를 읽어 메모 목록으로 나눈다.
   - 캡처 위에 그린 동그라미 · 손글씨도 보려고 쪽마다 그림으로도 읽는다.
   - **고치지 않는다.** 나누기만 한다. AI 작업이 도는 중에도 올릴 수 있다.
2. 카드에 항목 목록이 나온다. 항목마다
   - 글 고치기 · 종류 바꾸기 · 체크를 풀어 빼기
   - "N쪽" 링크로 원본 쪽 확인
   - 자리가 모호한 항목은 ❓ 질문이 붙는다
3. **[대기열에 넣기]** — 그때부터 위 메모 흐름대로 처리된다.
   - 각 메모 끝에 요청서 원문과 **원본 쪽 그림 경로**가 붙어, 처리하는 AI 가 원본을 직접 본다.

### 2-4-1. 음성 파일 넣기

Typecast 웹 편집기 등에서 **대사 한 줄마다 따로** 받은 음성 파일을 차시에 넣는다. 초안 파이프라인 화면에도 같은 기능이 있다.

1. 카드의 **[음성 파일 넣기]** 를 펼치고 범위를 고른다 — **빈 대사만 채우기**(기본) / **교체 포함(모든 대사)**.
2. 파일 여러 개를 한꺼번에 고르고 **[올려서 짝짓기]**.
3. 확인표가 나온다 — 대사마다 자동으로 짝지은 파일과 짝지은 방법.
   - **글자**: 파일 이름에 대사 앞부분이 있어서 짝지음(믿을 만함)
   - **순서**: 이름 속 번호(없으면 이름) 순서로 짝지음 → **꼭 들어 볼 것**
   - **직접**: 사람이 바꾼 것
   - ▶ 새 파일 듣기 · ▶ 지금 소리 듣기(교체할 때). 다른 파일로 바꾸거나 "넣지 않음"으로 뺀다. 짝 없는 파일은 위에 따로 보인다.
4. **[넣기]** — 파일을 `assets/audio/narration/` 에 놓고 lesson.json 에 건다. 바로 빌드한다.
   - 교체된 예전 파일은 다른 곳에서 안 쓰면 `desk/{차시}/removed/voice-*/` 로 옮긴다(지우지 않는다). 효과음은 건드리지 않는다.
   - lesson.json 은 원래 형식 그대로 다시 써서, git 에는 소리를 건 자리만 바뀐 것으로 보인다.
   - 올린 뒤 대사 글이 바뀌었으면 넣지 않고 다시 올리라고 한다. AI 작업이 도는 중에는 넣을 수 없다.

### 2-5. 커밋 전 점검

gyo6 `docs/DELIVERY_QA_CHECKLIST.md`(33개 항목)를 이 차시에 돌리고 **클로드가 걸린 것을 고친다.**

```text
작업 전 백업 → 빌드 → 코드 점검 → 클로드 점검·고침 → 다시 빌드 → 다시 코드 점검 → 보고서
```

- **코드 점검**(무료, 몇 초): 외부 URL · png/wav 잔존 · console · 그림 404 · 파일명 · 잔재 · 안 쓰는 파일 등 명령으로 재는 항목.
- **클로드 점검 · 고침**: 화면 · 판단 항목(겹침 · 줄바꿈 · 모바일 회전 · 화풍 등)까지 보고, **차시 폴더 안에서 고칠 수 있는 것은 고친다.**
- **다시 재서 통과해야 "고침"** 으로 센다(AI 가 고쳤다고 해도 믿지 않고 잰다).
- **고치지 않는 것**: 공통 런타임 · 빌드 설정 문제(예: minify), 그림을 다시 그려야 하는 것 → "남은 일"로 적는다.
  남은 실패의 **[메모로]** 는 남은 일을 적기 칸에 옮긴다.
- 실패하거나 멈추면 클로드가 고친 것을 **전부 되돌린다.**
- 결과는 카드 **위쪽**(상태 줄 바로 아래)에 남은 실패 → 확인 필요 → 고친 것(바꾼 파일) 순서로 나온다.
- 보고서는 `desk/{차시}/qa/{작업 번호}/report.md` — 작업대에만 남겨 gyo6 를 더럽히지 않는다.

### 2-6. 그 밖의 편의

| 기능 | 내용 |
|---|---|
| AI 사용량 | 작업마다 토큰 · 비용 · 시간(최근 10개). 토큰은 1a = 1, 1b = 1,000a, 1c = 1,000b 로 줄여 표시 |
| 알림 | Windows 바탕화면 알림 — 실패하면 바로, 대기열이 끝나면 요약. 실패 이유는 사람 말로(예: 코덱스 로그인 만료) |
| 작업 경로 | 차시마다 AI 가 고칠 폴더를 바꿀 수 있다([수정] · [기본으로]) |
| 화면 보기 | http 로 열어 글꼴까지 실제와 같게 보인다(`file://` 은 글꼴이 막힌다) |
| 사용법 | 작업대 맨 위 [사용법]을 펼치면 전체 설명 |

---

## 3. 켜기 · 다시 켜기

- 바탕화면 **「차시 작업대」 바로가기 하나**로 된다.
  - 꺼져 있으면 → 켠다
  - 켜져 있고 최신이면 → 브라우저만 연다
  - 켜져 있는데 **코드가 바뀌었으면** → 예전 작업대를 창째 끄고 새로 켠다(도는 작업이 있으면 알림 창으로 먼저 묻는다)
- 화면 맨 위 **빨간 띠** = 작업대 코드가 바뀌어 다시 켜야 한다는 뜻. 바로가기를 다시 누르면 된다.
- 작업대 창(검은 창, 최소화되어 있음)을 닫으면 작업대가 꺼지고 돌던 작업이 끊긴다(다음에 켤 때 되돌린다).

## 4. 누가 무엇을 하나

| | 클로드 | 코덱스 | 코드(AI 아님) | 사람 |
|---|---|---|---|---|
| **초안** | 기획 ~ 개발 | 그림 굽기 | 게이트 · manifest | 인터뷰 답 · 기준 그림 승인 |
| **작업대** | 코드 메모 · 요청서 나누기 · 커밋 전 점검 · 고침 | 그림 · 검증 메모 | 빌드 · 검사 · 백업 · 자가 검사 | 메모 적기 · 화면 보고 [완료] · 커밋 |

**AI 가 하지 않는 것** — 사람이 정한다.

- KB 서버 배포(gyo6 에서 `npm run deploy`)
- git 커밋 · 푸시
- 공통 런타임(`runtime/`) · 빌드 설정 수정
- 파일 지우기(보관 폴더로 옮기기만)

## 5. 파일이 어디에 남나

| 무엇 | 어디 |
|---|---|
| 차시 메모 | `desk/{학기-차시}/notes.json` |
| 작업 로그 · 이력 | `desk/{학기-차시}/jobs/` · `jobs.jsonl` |
| 작업 전 백업 | `desk/{학기-차시}/backup/{작업 번호}/` |
| AI 가 치운 파일 | `desk/{학기-차시}/removed/` · 되돌릴 때 새로 생긴 파일은 `orphans/` |
| 그림 작업 결과 사본 | `desk/{학기-차시}/after/{작업 번호}/` |
| 수정 요청서 | `desk/{학기-차시}/requests/{작업 번호}/` |
| 커밋 전 점검 보고서 | `desk/{학기-차시}/qa/{작업 번호}/report.md` |
| 초안 run | `runs/{run 이름}/` |
| 설정(모델 · gyo6 경로) | `desk/config.json` |
