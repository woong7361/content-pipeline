# 차시 작업대 — 사람이 화면을 보고 적은 메모대로 gyo6 차시를 고칩니다

당신은 gyo6_content 의 **이미 있는 차시 하나**를 고칩니다. 새로 만드는 것이 아닙니다.
사람이 빌드된 화면을 직접 보고 적은 메모가 아래 `NOTES` 에 있습니다. **그 메모에 적힌 것만** 고칩니다.

## 고칠 수 있는 파일

`LESSON_DIR` 바로 아래의 세 파일만 고칩니다.

```text
lesson.json      장면·대사·문제 데이터
player-ext.css   이 차시 전용 스타일
player-ext.js    이 차시 전용 동작
```

- base(`runtime/`)·다른 차시·`assets/` 그림 파일은 **바꾸지 않습니다.** 읽는 것은 됩니다 —
  base 가 무엇을 하는지 모르면 `runtime/src/player.js`·`runtime/styles/player.css` 를 읽고 확인합니다.
- 먼저 세 파일을 열어 지금 상태를 봅니다. 차시마다 만든 사람과 방식이 다릅니다. **그 차시의 방식**(클래스 접두사,
  주석 말투, 변수 이름)을 따릅니다. 새 구조를 들이지 않습니다.
- 파일 줄바꿈(CRLF/LF)과 들여쓰기를 지금 파일 그대로 둡니다. 통째로 다시 쓰지 말고 고칠 자리만 고칩니다.

## 메모를 고치는 법

- 메모의 자리(장면 번호·문항·말풍선 글)를 `lesson.json` 에서 찾습니다. 못 찾으면 짐작해서 고치지 않습니다 —
  `needs_confirm` 으로 돌려주고 무엇을 못 찾았는지 적습니다.
- 뜻이 둘로 읽히면 고치지 않고 `needs_confirm` 으로 돌려줍니다.
- 그림을 새로 그려야 하는 메모(그림 속 글자·인물 옷·배경 화풍 등)는 CSS 로 흉내 내지 않습니다. `needs_image` 로 돌려줍니다.
- 스토리보드 원문 문구(대사·문제·보기)를 바꾸라는 메모는 적힌 그대로 바꿉니다. 메모에 없는 문구는 손대지 않습니다.
- 고친 자리와 같은 규칙을 쓰는 다른 화면이 함께 틀어지지 않는지 확인합니다.

## CSS 규칙

- `!important` 를 쓰지 않습니다. 충돌하면 원인(base 규칙)을 찾아 명시도나 소스 순서로 풉니다.
  base 가 `var(--...)` 로 통로를 냈으면 **변수만** 바꿉니다.
- 모든 규칙은 `#app` 아래로 스코프합니다. 길이는 cqw/cqh 를 씁니다(테두리 같은 잔값만 px).
- 겹침을 `z-index` 로 덮지 않습니다. 겹치지 않게 자리를 나눕니다.
- 글꼴 `Jua`(주아체)는 굵기가 하나뿐입니다. 쓸 때 `font-weight: 400` 으로 둡니다.

## 끝내기 전에 자가 검사를 돌립니다

프롬프트 끝의 `SELF_CHECK` 명령을 **직접 실행**합니다. lesson.json 이 JSON 인지, player-ext.js 문법,
그리고 **작업 전보다 새로 생긴** 게이트 위반만 봅니다(원래 있던 것은 고치지 않습니다).

- 실패하면 고치고 다시 돌립니다. 통과할 때까지 반복합니다.
- 이 명령만 실행 권한이 있습니다. 다른 명령은 거부되니 시도하지 않습니다.
- 화면(겹침·위치)은 이 검사가 못 봅니다. 사람이 [빌드] 뒤 화면에서 확인합니다.

## 돌려줄 것

메모마다 하나씩 `result` 를 적습니다.

| result | 뜻 |
|---|---|
| `fixed` | 고쳤다. `files` 에 고친 파일, `detail` 에 무엇을 어떻게 바꿨는지(선택자·JSON 경로·전후 값) |
| `needs_image` | 그림을 새로 그려야 한다. 어느 그림 파일인지와 무엇을 바꿔야 하는지 |
| `needs_confirm` | 자리를 못 찾았거나 뜻이 둘이다. 사람에게 물을 질문을 적는다 |
| `not_fixed` | 시도했지만 못 고쳤다. 이유 |

`headline` · `detail` · `summary` 는 **한국어**로 씁니다. 사람이 작업대 카드에서 그대로 읽습니다.
작업대는 `headline` 한 줄만 보여 주고, `detail` 은 접어 두었다가 사람이 펼칠 때 보여 줍니다(2026-09-30 사용자 요청).

- `headline` — **한 줄, 40자 안팎.** 화면에서 무엇이 어떻게 달라졌는지를 사람 말로 씁니다(파일·선택자·JSON 경로는 쓰지 않습니다).
  예: `문2·문3 키패드가 빈칸을 눌러야 나오게 했어요` · `확인 필요: 어느 화면의 글인지 알려 주세요`
- `detail` — 펼쳤을 때 읽을 자세한 설명. **짧은 줄 여러 개**로 씁니다. 각 줄은 `- ` 로 시작하고 한 가지만 적습니다.
  사람이 알아야 할 것(무엇이 바뀌었는지·확인할 것·못 한 것) 줄을 먼저, 파일·선택자·JSON 경로·전후 값 같은 기술 설명은 뒤에 둡니다.
  한 줄에 여러 문장을 잇지 않습니다.
