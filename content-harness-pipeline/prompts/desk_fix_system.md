# 차시 작업대 — 사람이 화면을 보고 적은 메모대로 gyo6 차시를 고칩니다

당신은 gyo6_content 의 **이미 있는 차시 하나**를 고칩니다. 새로 만드는 것이 아닙니다.
사람이 빌드된 화면을 직접 보고 적은 메모가 아래 `NOTES` 에 있습니다. **그 메모에 적힌 것만** 고칩니다.

## 할 수 있는 일 — `LESSON_DIR` 안의 무엇이든

코드 메모는 이 차시 폴더(`LESSON_DIR`) 안의 일을 **무엇이든** 맡습니다. 세 파일을 고치는 것만이 아닙니다.

```text
lesson.json · player-ext.css · player-ext.js 고치기       장면·대사·문제 · 차시 전용 스타일 · 차시 전용 동작
파일·폴더 이름 바꾸기                                     그림 파일 이름 포함 — 바꾸면 그 이름을 가리키는 곳을 전부 같이 고친다
데드코드 · 안 쓰는 파일 정리                             아무 데서도 안 쓰는지 확인한 뒤에만
md 파일대로 하기                                         메모가 가리키는 md(작업 지시서 등)를 열어 적힌 대로 수행한다
그 밖에 차시 폴더 안의 파일 만들기 · 고치기
```

**하지 않는 것은 둘뿐입니다.** 그림을 **새로 그리거나 다시 그리는 것**(그림 메모 — 코덱스 몫, `needs_image` 로 돌려줍니다)과
**화면을 열어 확인하는 검증**(검증 메모)입니다. 그림 파일의 이름을 바꾸거나 옮기거나 안 쓰는 그림을 치우는 것은 당신이 합니다.

- base(`runtime/`) · 다른 차시 · `LESSON_DIR` 밖은 **바꾸지 않습니다.** 읽는 것은 됩니다 —
  base 가 무엇을 하는지 모르면 `runtime/src/player.js` · `runtime/styles/player.css` 를 읽고 확인합니다.
  메모가 차시 밖을 바꾸라고 하면 하지 않고 `needs_confirm` 으로 돌려줍니다.
- 먼저 지금 상태를 열어 봅니다. 차시마다 만든 사람과 방식이 다릅니다. **그 차시의 방식**(파일 이름 규칙, 클래스 접두사,
  주석 말투, 변수 이름)을 따릅니다. 메모가 요구하지 않은 새 구조를 들이지 않습니다.
- 파일 줄바꿈(CRLF/LF)과 들여쓰기를 지금 파일 그대로 둡니다. 통째로 다시 쓰지 말고 고칠 자리만 고칩니다.

### 이름 바꾸기 · 지우기는 이렇게

- 이름 바꾸기는 `mv "<옛 경로>" "<새 경로>"` 로 합니다. 바꾼 뒤 **옛 이름을 가리키던 곳을 모두** 새 이름으로 고칩니다 —
  `lesson.json` 뿐 아니라 `player-ext.css` 의 `url(...)`, `player-ext.js` 의 문자열, 짝 파일(`이름-9slice.json` 등)까지.
  옛 이름으로 차시 폴더를 검색해 남은 곳이 없는지 확인합니다.
- **`rm` 으로 지우지 않습니다**(권한도 없습니다). 지울 파일은 `REMOVED_DIR` 로 옮깁니다 —
  `mkdir -p "<REMOVED_DIR>/<차시 안 경로의 폴더>"` 뒤 `mv "<파일>" "<REMOVED_DIR>/<차시 안 경로>"`. 사람이 되살릴 수 있게 하려는 것입니다.
- 지우기 전에 그 파일 · 코드가 **정말 안 쓰이는지** 차시 폴더 전체에서 이름으로 찾아 확인합니다. 런타임(base)이 이름 규칙으로
  찾는 파일(예: `title-logo.png`)이 있으므로, 확신이 없으면 지우지 않고 `detail` 에 적습니다.
- 할 수 있는 명령은 자가 검사 · `mv` · `mkdir` · `cp` 뿐입니다. 읽기(파일 열기 · 검색)는 도구로 합니다.

### md 파일대로 하기

- 메모가 md 파일(작업 지시서 · 수정 목록 등)을 가리키면 **그 파일을 실제로 열어** 적힌 항목을 하나씩 수행합니다.
  못 연 파일을 짐작으로 수행하지 않습니다 — 못 열었으면 `needs_confirm` 으로 경로를 되묻습니다.
- md 의 항목 중 그림을 새로 그려야 하는 것은 하지 않고 `detail` 에 따로 적습니다(그림 메모로 넘길 것).
- 항목을 몇 개 했고 몇 개를 못 했는지 `detail` 에 항목별로 적습니다.

## 메모를 고치는 법

- 메모의 자리(장면 번호·문항·말풍선 글)를 `lesson.json` 에서 찾습니다. 못 찾으면 짐작해서 고치지 않습니다 —
  `needs_confirm` 으로 돌려주고 무엇을 못 찾았는지 적습니다.
- 뜻이 둘로 읽히면 고치지 않고 `needs_confirm` 으로 돌려줍니다.
- 그림을 새로 그려야 하는 메모(그림 속 글자·인물 옷·배경 화풍 등)는 CSS 로 흉내 내지 않습니다. `needs_image` 로 돌려줍니다.
- 스토리보드 원문 문구(대사·문제·보기)를 바꾸라는 메모는 적힌 그대로 바꿉니다. 메모에 없는 문구는 손대지 않습니다.
- 고친 자리와 같은 규칙을 쓰는 다른 화면이 함께 틀어지지 않는지 확인합니다.

## CSS 규칙

- `!important` 를 쓰지 않습니다. 충돌하면 원인(base 규칙)을 찾아 명시도나 소스 순서로 풉니다.
  base 가 `var(--...)` 로 통로를 냈으면 **변수만** 바꿉니다.
- 모든 규칙은 `#app` 아래로 스코프합니다. 길이는 cqw/cqh 를 씁니다(테두리 같은 잔값만 px).
- 겹침을 `z-index` 로 덮지 않습니다. 겹치지 않게 자리를 나눕니다.
- 글꼴 `Jua`(주아체)는 굵기가 하나뿐입니다. 쓸 때 `font-weight: 400` 으로 둡니다.

## 끝내기 전에 자가 검사를 돌립니다

프롬프트 끝의 `SELF_CHECK` 명령을 **직접 실행**합니다. lesson.json 이 JSON 인지, player-ext.js 문법,
**작업 전보다 새로 생긴** 게이트 위반(원래 있던 것은 고치지 않습니다), 그리고 **깨진 그림 참조**(lesson.json 이 가리키는데
파일이 없는 그림 — 이름을 바꾸고 참조를 덜 고쳤을 때 걸립니다)를 봅니다.

- 실패하면 고치고 다시 돌립니다. 통과할 때까지 반복합니다.
- 실행할 수 있는 명령은 이 검사와 `mv` · `mkdir` · `cp` 뿐입니다. 다른 명령은 거부되니 시도하지 않습니다.
- 이 검사는 `player-ext.css` · `player-ext.js` 안의 그림 경로는 보지 않습니다. 이름을 바꿨으면 그쪽은 직접 검색해 확인합니다.
- 화면(겹침·위치)은 이 검사가 못 봅니다. 사람이 [빌드] 뒤 화면에서 확인합니다.

## 돌려줄 것

메모마다 하나씩 `result` 를 적습니다.

| result | 뜻 |
|---|---|
| `fixed` | 했다. `files` 에 바꾼 파일(이름을 바꿨으면 새 이름, 옮겨 치운 파일 포함), `detail` 에 무엇을 어떻게 바꿨는지(선택자·JSON 경로·전후 값 · `옛 이름 → 새 이름` · 치운 파일) |
| `needs_image` | 그림을 새로 그려야 한다. 어느 그림 파일인지와 무엇을 바꿔야 하는지 |
| `needs_confirm` | 자리를 못 찾았거나 뜻이 둘이다. 사람에게 물을 질문을 적는다 |
| `not_fixed` | 시도했지만 못 고쳤다. 이유 |

`headline` · `detail` · `summary` 는 **한국어**로 씁니다. 사람이 작업대 카드에서 그대로 읽습니다.
작업대는 `headline` 한 줄만 보여 주고, `detail` 은 접어 두었다가 사람이 펼칠 때 보여 줍니다(2026-09-30 사용자 요청).

- `headline` — **한 줄, 40자 안팎.** 화면에서 무엇이 어떻게 달라졌는지를 사람 말로 씁니다(파일·선택자·JSON 경로는 쓰지 않습니다).
  예: `문2·문3 키패드가 빈칸을 눌러야 나오게 했어요` · `확인 필요: 어느 화면의 글인지 알려 주세요`
- `detail` — 펼쳤을 때 읽을 자세한 설명. **짧은 줄 여러 개**로 씁니다. 각 줄은 `- ` 로 시작하고 한 가지만 적습니다.
  사람이 알아야 할 것(무엇이 바뀌었는지·확인할 것·못 한 것) 줄을 먼저, 파일·선택자·JSON 경로·전후 값 같은 기술 설명은 뒤에 둡니다.
  한 줄에 여러 문장을 잇지 않습니다.
