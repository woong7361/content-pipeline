# 1학년 2학기 8차시 — 알록달록, 학교 담장 색칠하기

## 이 디렉토리

`production/1-2/08`은 8차시 콘텐츠의 산출물 디렉토리다.

```text
index.html            차시 본체(단일 파일, 인라인 CSS/JS)
assets/               차시 전용 이미지
dfbc1027_input.json   파이프라인 입력
dfbc1027_planner.json 파이프라인 planner 산출물
todo.md               앞으로 수정할 내용
complete.md           완료된 항목 보관소(todo.md에서 옮겨온 것)
```

## 작업 지시는 todo.md에 있다

**이 차시에서 앞으로 할 작업은 `todo.md`에 정리되어 있다.** 수정 작업을 시작하기 전에 `todo.md`를 먼저 읽는다.

- 새로운 수정 요청을 받으면 바로 고치지 말고 `todo.md`에 먼저 항목을 추가한 뒤 작업한다.
- 결과 품질에 대한 지적·교정 피드백은 워크스페이스 최상단 `problem.md` 루프(최상위 `CLAUDE.md` 참조)도 함께 따른다.

### 완료하면 todo.md를 업데이트한다

**작업을 끝냈으면 `todo.md`의 해당 항목에 "어떻게 해서 완료했는지"를 간단히 적는다.** 상태만 `완료`로 바꾸고 끝내지 않는다.

- 상태를 `완료 (YYYY-MM-DD)`로 바꾼다.
- `- 조치:` 줄에 **무엇을 어떻게 고쳤는지 2~4줄로** 적는다. 바꾼 선택자·함수·파일명은 실제 이름 그대로 쓴다(나중에 검색으로 찾을 수 있어야 한다).
- 다음 셋 중 해당하는 것만 덧붙인다. 없으면 생략한다.
  - **검증**: 어떻게 확인했는지 한 줄 (예: "headless Chrome 1920x1080 캡처로 8개 씬 전수 확인")
  - **주의**: 다른 항목이 이걸 건드리면 깨지는 부분, 또는 예상과 달랐던 점
  - **미해결**: 일부만 끝냈으면 상태를 `진행중`으로 두고 남은 것을 적는다
- **분량은 짧게.** 작업 과정을 서술하지 말고 결과와 근거만 남긴다. 시행착오는 다음 사람에게 필요한 것(왜 그 방법이 아니어야 했는지)만 적는다.
- 작업 중 새로 알게 된 확인 필요 사항은 `todo.md` 하단 "확인이 필요한 항목 정리"에 추가한다.
- 다른 항목에 영향을 주는 변경이면 "항목 간 의존 관계"에도 한 줄 추가한다.

### 완료 항목은 complete.md로 옮긴다

**`todo.md`는 "앞으로 할 일"만 담는다.** 완료 기록이 쌓여 파일이 두꺼워지면 `todo.md`를 읽는 비용이 커지고 남은 작업이 묻힌다.

- 항목 상태가 `완료`가 되면, 그 항목 블록(제목 + 상태 + 조치 + 검증/주의)을 **통째로 잘라 `complete.md`로 옮긴다.** 내용을 요약하거나 줄이지 않는다.
- `complete.md`에서는 완료 날짜 순으로 뒤에 덧붙인다. 항목 번호는 `todo.md`에 있던 번호를 그대로 유지한다(예: `## 7. "수리가 필요해요 1"의 모양 찾기 대폭 변경`). 번호를 다시 매기지 않는다 — 다른 항목이 번호로 참조하고 있다.
- `todo.md`의 "확인이 필요한 항목 정리"와 "항목 간 의존 관계"는 옮기지 않고 `todo.md`에 남긴다. 아직 유효한 정보다.
- 옮기는 시점은 **작업 단락이 끝났을 때**다. 작업 중간에 옮기지 않는다.
- 과거 조치 내용을 찾을 때는 `todo.md`와 `complete.md`를 **둘 다** 검색한다.

## 1-2/01은 같은 선생님의 스토리보드다

`production/1-2/01` (와글와글, 운동회를 도와요!)은 **같은 선생님이 만든 같은 시리즈의 스토리보드**다. 따라서 8차시는 1차시와 하나의 코스처럼 보여야 한다.

### 반드시 동일해야 하는 것

**화풍(art direction)** — 협상 대상이 아니다. 두 차시의 에셋이 나란히 놓였을 때 같은 작가가 그린 것으로 보여야 한다.

`1-2/01/lesson.json`의 `artDirection`이 기준이다.

- 매체: 2D 벡터 일러스트레이션
- 룩: 초등 저학년 교과서·동화풍, 굵고 깔끔한 외곽선, 플랫 셰이딩(약한 그라데이션까지 허용)
- 팔레트: 따뜻한 파스텔 — 하늘색, 잔디 초록, 흙 갈색, 크림 화이트 / 포인트 청·홍
- 조명: 맑은 한낮, 부드러운 그림자. 고대비·드라마틱 조명 금지
- 선: 균일한 중간 두께 외곽선
- 렌더링: 납작하고 깔끔하게. 사진실사·3D 렌더·과한 텍스처·노이즈 금지

새 에셋을 만들 때는 `1-2/01/lesson.json`의 `artDirection`을 그대로 읽어서 프롬프트에 반영한다. 기억에 의존해 재작성하지 않는다.

## 구조 차이 주의

두 차시는 렌더링 구조가 다르다.

- **1-2/01**: 데이터 주도. `lesson.json`을 인라인한 전역 `L` 객체를 읽어 `#content`에 씬을 동적 렌더링한다. 캐릭터/말풍선은 `.charzone` 하나를 공유한다.
- **1-2/08**: 정적 마크업. `<section class="scene">`을 순서대로 나열하고 `active` 클래스로 전환한다. 캐릭터/말풍선이 씬마다 개별로 들어 있다.

따라서 01의 코드를 그대로 복사하면 동작하지 않는 경우가 있다. **시각적 결과(CSS·에셋·애니메이션)는 01과 동일하게 맞추되, 렌더링 방식은 08의 정적 씬 구조를 유지한다.** 08을 데이터 주도로 갈아엎는 것은 이 작업의 범위가 아니며, 필요하다고 판단되면 먼저 사용자에게 확인한다.

## 에셋 규칙

- 새 에셋은 `assets/`에 넣고 파일명은 기존 컨벤션(`kebab-case`, 역할 기반: `school-wall-damaged.png`, `teacher-praising.png`)을 따른다.
- 캐릭터는 `{역할}-{상태}` 형태다: `worker-idle` / `worker-explaining` / `worker-apologizing`, `teacher-idle` / `teacher-explaining` / `teacher-praising`, `student-idle` / `student-thinking` / `student-volunteer`.
- UI 위에 얹는 요소(도형 타일, 스탬프, 힌트 등)는 **배경을 투명하게** 만든다. 배경색이 박힌 PNG를 씬 위에 올리지 않는다.
- 텍스트가 필요한 이미지는 이미지에 글자를 굽지 말고 빈 면을 남긴 뒤 HTML 텍스트를 얹는다(현재 `*-body.png` 에셋들이 이 규칙을 따르고 있다).
